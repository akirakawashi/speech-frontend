# Speech Analytics — фронтенд

Интерфейс поиска по расшифровкам разговоров колл-центра. Отдельный репозиторий
(решение S-06); бэкенд — `speech-ms` в `aicistent-backend`.

Проектная документация: `aicistent-documentation/speech-analytics/`.

## Стек

Next.js 15 App Router, React 19, TypeScript strict, Biome, Vitest, Playwright,
TanStack Query, CSS Modules поверх токенов из `src/app/globals.css`.

## Конфигурация — в рантайме, не в бандле

`GET /config.json` читает окружение процесса при каждом запросе:

| Переменная | Умолчание | Что это |
|---|---|---|
| `SPEECH_API_URL` | пусто | адрес `speech-ms`; пусто — тот же источник (за общим nginx) |
| `SPEECH_AUTH_MODE` | `keycloak` | `open` пропускает вход; всё, кроме `open`, — это `keycloak` |
| `SPEECH_KEYCLOAK_URL` | пусто | базовый адрес Keycloak |
| `SPEECH_KEYCLOAK_REALM` | пусто | realm |
| `SPEECH_KEYCLOAK_CLIENT_ID` | пусто | клиент |
| `SPEECH_KEYCLOAK_RESPONSE_MODE` | `fragment` | код не должен попадать в строку запроса |
| `SPEECH_KEYCLOAK_SCOPE` | `openid profile email` | |
| `SPEECH_KEYCLOAK_PKCE_ENABLED` | `true` | выключается только явным `false` |
| `SPEECH_DISPLAY_TIMEZONE` | `Europe/Moscow` | только отображение; хранится всё в UTC |

Один образ работает на любом стенде. Это прямое следствие дефектов 17/19/22/28
журнала альфа-миграции, где `VITE_*` запекались в бандл и расходились с
раскладкой развёртывания.

## Разработка

```bash
pnpm install
pnpm api:types      # типы из ../aicistent-backend/openapi.speech.json
pnpm dev            # http://127.0.0.1:3000
pnpm typecheck && pnpm lint && pnpm test
```

Нужен поднятый `speech-ms`. Настройки берутся из `.env.local` (скопируй из
`.env.example`), там же `SPEECH_AUTH_MODE=open` — пока проекту не выделен
Keycloak, иначе приложение не открыть.

```bash
# API рядом, в режиме open
docker run -d --name speech-ms-dev -p 18096:8096   -e APP_ENV=local -e SPEECH_AUTH_MODE=open   -e SPEECH_MS_DATABASE_URL="postgresql+asyncpg://…/speech"   aicistent-speech-ms:local
docker network connect local_data speech-ms-dev   # если Postgres в этой сети

pnpm dev   # http://127.0.0.1:3000
```

`/api/...` пробрасывает сам фронт — обработчик `src/app/api/[...path]/route.ts`,
адрес `speech-ms` берётся из `SPEECH_API_PROXY_TARGET` в момент запроса. Так и в
разработке, и в контейнере: 2026-09-15 эксплуатация опубликовала
`speech.ic-group.ru` целиком на порт фронта, а своего прокси перед ним нет.
`SPEECH_API_URL` остаётся пустым, браузер ходит по относительному пути, и CORS не
нужен нигде.

Раньше проброс жил в `rewrites()` `next.config.ts` под переменной разработки — и
запёкся в образ из `.env.local`: продуктивный контейнер слал `/api` на
`127.0.0.1:18096`, то есть в самого себя, и отвечал `500`. Поэтому `.env*` теперь
в `.dockerignore`, а переменные сборки фронту по-прежнему не нужны.

## Разговор — рядом с выдачей, а не поверх неё

`/calls/<id>` — тот же экран диалогов, которому передана панель разговора. Она
встаёт в правую колонку сетки `1.3fr / 1fr` **внутри** контента и липнет к верху
при прокрутке.

Так было не всегда, и обратно лучше не возвращаться. Первая редакция делила
окно: `height: 100vh`, две колонки, у каждой своя прокрутка. Панель при этом
прибита к краю окна, не считается с шириной контента и обрезается там, где окно
кончается, — со стороны это выглядит как всплывающее окно поверх экрана, а не
как часть страницы.

Два следствия, которые легко потерять при правках:

* **Панель рисуется при любом состоянии выдачи**, а не только когда что-то
  найдено. Ссылку на разговор присылают коллеге, и открывается она без
  параметров поиска: период умалчивается в тридцать дней, старый разговор в них
  не попадает, выдача пуста — а разговор показать обязаны.
* **Ссылка карточки несёт всё состояние экрана**, а не один запрос. Страница
  разбирает адрес заново и строит по нему выдачу слева; потеряв период, она
  показывает пустоту рядом с открытой панелью.

На узком экране (до 1100px) панель встаёт над выдачей, а не прячет её.

## Экраны администрирования

`/admin` — семь экранов поверх админ-API: пайплайн, задания, темы, проекты,
настройки, журнал, пользователи. Своей «главной» у раздела нет: `/admin`
открывает пайплайн, за ним и приходят, когда что-то идёт не так.

Право `admin` проверяется один раз на весь раздел. Это **не защита**, а
удобство: решение принимает ручка сервиса, и раздел откажет тому, кто наберёт
адрес руками. Но показывать семь экранов, каждый из которых ответит `403`, тоже
нельзя — человек решит, что сломан сервис, а сломан у него доступ.

Несколько вещей, которые легко сломать обратно:

* **Подпись поля связывается через `htmlFor`, а не обёрткой `<label>`.** Обёртка
  собирает доступное имя из всего содержимого метки, включая тексты вариантов
  выпадающего списка: «Этаплюбойприёмрасшифровка…». У поля ввода этого не видно
  — у него нет содержимого, — поэтому ошибка доживает до первого `<select>`.
  Общий `Field` в `components/admin/shared.tsx` делает это правильно.
* **`ActionResponse.detail` — машинное поле, а не сообщение.** У переобработки
  там код этапа, у остальных действий `null`. Показывать его в баннере нельзя;
  текст собирается из `changed`.
* **Коды отказов переводятся на клиенте** (`REFUSAL_TEXT`). Сервер отвечает
  машине, и его коды нужны такими в тестах и логах. Неизвестный код показывается
  как есть: выдуманное объяснение хуже непонятного — по коду можно спросить.
* **Настройки отправляются разницей, а не целиком.** «Задано» на экране означает
  «в базе есть строка для ключа»; отправив все значения, интерфейс пометил бы
  заданными все восемь. И это именно «задано», а не «отличается от умолчания»:
  выставленное значение переживёт смену умолчания.

## Сквозные прогоны (Playwright)

```bash
pnpm e2e
```

Идут против **поднятого стенда**, а не против моков: вопрос не в том, рисуют ли
компоненты переданное, а в том, договариваются ли фронт и сервер о форме данных.
Поэтому нужен работающий `speech-ms` и данные в базе.

**Набору нужен непустой корпус — и больше ничего.** Каким он засеян, значения
не имеет: подойдёт и настоящая выгрузка, и синтетика. Раньше здесь стоял
порядок из четырёх шагов, потому что тесты опирались на конкретный сидовый
набор — конкретный телефон, конкретный таймкод, звонки за последние тридцать
дней. В день, когда на стенде оказалась настоящая январская выгрузка,
четырнадцать тестов покраснели, не найдя ни одного дефекта.

Теперь те, кому нужна непустая выдача, открывают экран сразу «за всё время», а
состояния, которых нельзя добиться через интерфейс, тесты создают и снимают
сами — `e2e/stand.ts`:

* «запись удалена по сроку хранения» и «записи не было у источника» — пометка
  на существующем звонке, снимается в `finally`;
* запись длиннее получаса — тишина на 35 минут, `ffmpeg` в контейнере воркера,
  `mc` кладёт её в бакет; строка звонка и объект удаляются вместе. Нужна
  потому, что критерий SP-505 назван в минутах, а самый длинный настоящий
  разговор в корпусе — четырнадцать.

Обращения к Postgres и MinIO идут через `docker exec`: порт базы на стенде
наружу не опубликован, и публиковать его ради тестов не нужно. Имена
контейнеров переопределяются переменными `SPEECH_E2E_*` (см. `e2e/stand.ts`).

**Тесты сервиса на живой базе больше не могут унести корпус.** Они требуют
базы, названной тестовой (`speech_test`), и против рабочей просто не
собираются — см. `tests/speech_db_support.py` в бэкенде.

Прогон идёт в один поток намеренно: `next dev` компилирует маршрут при первом
обращении, и девять параллельных тестов на ненагретые страницы дают падения,
которых нет в поведении приложения.

**И не запускай `next build`, пока работает `next dev`** — оба пишут в `.next`,
и продакшен-сборка ломает раздачу чанков дев-серверу. Проявляется как `404` на
все `_next/static/*` в уже открытой вкладке. Лечится `rm -rf .next` и
перезапуском.

## Версии инструментов

Две версии закреплены **точно**, без `^`, и это не педантизм:

* `packageManager: pnpm@9.15.9` — иначе corepack тянет в образ «последний»
  pnpm, а он в другой мажорной версии отвергает лок-файл по своим политикам.
  Сборка образа ломалась от календаря, а не от кода.
* `@biomejs/biome` — в `biome.json` записан адрес схемы с номером версии, и
  диапазон `^` разводил их между собой: конфигурация от 2.5.9, CLI 2.5.12,
  предупреждение на каждом запуске. Адрес схемы правится вместе с версией; если
  кто-то поднимет одно и забудет второе, Biome об этом скажет — и это полезный
  сигнал, а не шум.

Остальные зависимости живут с `^`: `pnpm-lock.yaml` делает установку
воспроизводимой, а номера версий нигде больше не продублированы.

## Типы API

`src/api/schema.d.ts` порождается из `openapi.speech.json` бэкенда и в правках
руками не нуждается. Схема выгружается на стороне бэкенда:

```bash
python -c "import json;from app.core.config import Settings;from app.speech_service.main import create_app;json.dump(create_app(Settings(_env_file=None, app_env='local', speech_auth_mode='open')).openapi(), open('openapi.speech.json','w',encoding='utf-8'), ensure_ascii=False, indent=2, sort_keys=True)"
```
